# ballware Meta Service — documentation

payloads, metadata model, tenancy and authorization behavior, and the OpenAPI snapshots the pages are
derived from.

> Scope note: this is the **backend view** of the service. The frontend consumption contract (how the
> metadata payloads are interpreted by the UI framework) lives in `ballware-angular/docs/metadata` and
> is not duplicated here.

## Quick facts

- Two OpenAPI documents per service: `meta` ("ballware Meta API", 150 paths, 25 schemas) and
  `service` ("ballware Service API", 17 paths, 24 schemas), OpenAPI `3.0.4`
  (`src/Ballware.Meta.Service/Startup.cs:355-365`).
- Swagger UI: `https://localhost:6001/swagger`; raw documents at `/swagger/meta/swagger.json` and
  `/swagger/service/swagger.json` (`src/Ballware.Meta.Service/Startup.cs:480-497`).
- Committed OpenAPI snapshots: [openapi/meta.json](openapi/meta.json),
  [openapi/service.json](openapi/service.json), generated by
  [openapi/fetch-spec.sh](openapi/fetch-spec.sh).
- Development ports: HTTP `http://localhost:5001` (Kestrel config in
  `src/Ballware.Meta.Service/appsettings.Development.json`) plus HTTPS `https://localhost:6001` for
  browser use (see the repository `README.md`); in `ballware-docker-compose` the service publishes
  HTTP `5001`.
- Authentication: JWT bearer against an OIDC issuer; authorization by scope → policy
  (`metaApi` for Meta API operations, `serviceApi` for Service API operations,
  `src/Ballware.Meta.Service/Startup.cs:191-204`).
- JSON bodies are PascalCase (`src/Ballware.Meta.Service/Startup.cs:52-60`).

## Request flow

```text
client (browser / other service)
  |  Authorization: Bearer <token>
  v
ASP.NET Core routing + JWT bearer authentication        Startup.cs:156-189
  |  scope claim -> policy "metaApi" / "serviceApi"      Startup.cs:191-204
  v
endpoint handler (generic CRUD or specific read)
  |  generic editing handlers resolve the tenant from
  |  the "tenant" claim; service handlers take
  |  explicit {tenantId} path segments
  v
tenant + entity rights check (Jint scripts)              ballware-shared-dotnet
  |  candidate "<application>.<entity>.<right>"
  |  evaluated by tenant RightsCheckScript, then
  |  entity CustomScripts.extendedRightsCheck
  v
repository (tenant-aware, optionally cached)             Startup.cs:307-322
  v
EF Core on the metadata DB  +  tenant business schemas
  |  schema provisioning via repository hooks            Startup.cs:307-308
  v
Storage Service (temporary/export files) and             Startup.cs:251-273
Schema Service (generated tenant schemas), called
with OAuth2 client-credentials tokens                    Startup.cs:229-249
```

For setup and configuration see the repository [README.md](../README.md). For OpenAPI regeneration see
[openapi/README.md](openapi/README.md).
